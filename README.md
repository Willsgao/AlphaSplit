# AlphaSplit

> *Alpha is earned. Value should be split.*

**多智能体协商 + 可审计贡献值公式的金融知识工作分配 Demo**

面向：[第五届中国研究生金融科技创新大赛](https://cpipc.acge.org.cn/cw/hp/2c90800c8093eef401809d3501080654)  
赛道：自拟题目 · **人工智能技术在金融领域的创新应用**

---

## 一句话

用 Multi-Agent 协商呈现各方主张，用贡献值公式给出可审计落账——回答量化平台里绕不开的问题：

> 因子是研究员开发的，钱是策略线赚的，复用产生的超额收益该怎么分？

---

## 要解决什么问题

平台型量化私募常见结构：中央研究产出因子，多条策略线复用；传统 KPI 下利润跟账户走，研究员拿固定包，**层积式复用价值断档**。

本 Demo 场景（合成数据）：

| 角色 | 主张 | 关键事实 |
|------|------|----------|
| 李量化（研究员） | 要 40% | 波动率因子被两条线复用，归因超额合计约 ¥2,000 万 |
| 张经理（指数增强 PM） | 要 45% | AUM ¥5 亿，超额 12%，IR 3.0，执行侧权重高 |
| 陈经理（市场中性 PM） | 要 35% | AUM ¥3 亿，纯 Alpha，更依赖因子质量 |
| 合计 | **120%** | 冲突无法靠「各说各话」直接加总 |

年终可协商奖金池 ¥500 万（平台先扣 25%，可分配 ¥375 万）。

## 怎么解

```
各方主张（可冲突）
        │
        ▼
  Multi-Agent 多轮协商  ── Mock 路演稳定 / 可选 LLM
        │
        ▼
  贡献值公式终裁落账     ── 可重复、可审计
        │
        ▼
  三组机制对照           ── KPI vs 公式 vs Agent+公式
```

**设计原则**：协商解决「被听见」与立场表达；公式守住公平下限与终裁一致性。  
当前 Demo **默认自动跑完**（尚无人机对话改份额）；落地形态应保留人工审批接口（见下方边界）。

### 贡献值公式

```
C = Labor × Impact × Scarcity × Reuse
份额 = C_i / ΣC ，金额 = 份额 × 可分配池
```

| 维度 | 含义 |
|------|------|
| Labor | `hours × (complexity / 5)` |
| Impact | 场景显式 `impact_score`（可审计标定；缺省可回退推导） |
| Scarcity | `1 / (1 + k · pool_size)` |
| Reuse | `1 + ρ · (reuse_count − 1)`（因子多策略复用加成） |

### 本场景标定结果（张 > 李 > 陈）

| 角色 | Impact | 公式份额 | 金额（约） | 叙事含义 |
|------|--------|----------|------------|----------|
| 张经理 | 0.78 | **38.3%** | ¥144 万 | AUM 更大、执行变现权重最高 |
| 李量化 | 0.55 | **34.4%** | ¥129 万 | 稀缺研发 + 双策略复用 |
| 陈经理 | 0.55 | **27.3%** | ¥102 万 | 更吃因子，执行侧不压过 ¥5 亿线 PM |

`impact_score` 与说明写在 `data/scenarios/quant_fund.json`，评委可直接打开核对。

## 快速开始

```bash
# 仓库根目录
pip install -r requirements.txt

# 终端 Demo（无需浏览器）
python -m engine.simulate

# Web Demo（Chart.js 已本地化，可离线路演）
python -m engine.api.main
# 浏览器打开 http://127.0.0.1:8000 →「运行完整 Demo」
```

可选 LLM 协商（未配置 Key 或调用失败时自动回退 Mock）：

```bash
# Windows PowerShell
$env:DEEPSEEK_API_KEY="sk-xxx"
python -m engine.api.main --mode llm
```

运行测试：

```bash
python -m unittest tests.test_agentic -v
```

## 三组对照（机制仿真，非历史回测）

同一场景参数下比较三种分配规则：

| 组别 | 规则 | 预期特征 |
|------|------|----------|
| KPI | 利润跟账户，研究员固定小份额 | 高不均、低复用激励 |
| 公式 | 纯贡献值分配 | 客观、可审计 |
| Agent+公式 | 协商过程 + 公式终裁 | 同审计份额，满意度更高 |

演化结果带受控噪声，用于展示机制差异趋势；**不是**真实基金薪酬回测。详见 Web「三组对照 / 演化曲线」与 `docs/ARCHITECTURE.md`。

## 诚实边界（答辩建议主动说明）

| 是 | 不是 |
|----|------|
| 真实行业痛点的机制演示 | 某家私募真实奖金系统的复现 |

| Mock 保路演 + 可选 LLM | 已上线的多智能体薪酬产品 |

生产落地还需：归因系统接入、HR/绩效与合规审批、人工最终确认权。
