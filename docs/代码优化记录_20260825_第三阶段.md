# AlphaSplit 第三阶段代码优化记录（2026-08-25）

## 1. 优化目标与边界

本阶段针对“个股分析师和策略分析师证据轨建议权重为 0”进行角色链路审查与修复。

优化目标：

1. 让每个角色在回测中承担清晰、独立且可检验的职责；
2. 修复会压缩或混淆角色边际贡献的实现问题；
3. 在不使用未来数据的前提下改善策略择时逻辑；
4. 重新执行完整 32 联盟 Shapley 回测；
5. 统一前端“制度轨 60% + 证据轨 40%”口径。

本阶段明确不采用以下做法：

- 不把负贡献强制改为正贡献；
- 不为每个角色设置最低证据轨权重；
- 不反复更换参数或样本区间，直到五个角色全部转正；
- 不使用持有期结束后才能获得的数据生成月初信号。

因此，“尽量为正”是通过修正职责和反事实公平性实现，而不是保证任意样本内五个角色都为正。

## 2. 问题诊断

### 2.1 个股分析师与量化分析师职责重叠

旧流程中，个股分析师直接选出最终 10 只股票。量化分析师没有稳定的候选池优化空间，其边际职责不清晰。

同时发现一个关键路由错误：量化优化器调用时传入的是“个股分析师”角色名，导致优化器继续读取个股因子，而非量化分析师自己的因子。该问题会扭曲两个角色的 Shapley 边际贡献。

### 2.2 量化缺席的反事实不公平

量化分析师缺席时，旧流程可能对候选列表进行与职责无关的截断。新的反事实定义为：

- 个股分析师在场、量化分析师缺席：保留个股排名前 10；
- 个股与量化均缺席：才使用确定性中性选择；
- 量化分析师在场：使用量化因子从个股候选池优化到最终 10 只。

这样可以确保 Shapley 联盟中“移除量化角色”只移除量化职责，不同时破坏个股角色已经产生的排名信息。

### 2.3 策略分析师原择时过于单一

旧策略仅按目标波动率机械降仓。在上涨趋势中，高波动并不必然代表应降低风险暴露，因此容易在强势行情中持续少赚。

新策略增加趋势确认：

1. 仅读取持有月月初之前的历史指数收益；
2. 历史样本不足时保持满仓；
3. 最近窗口累计趋势非负时保持满仓；
4. 只有趋势为负且波动较高时，才按目标波动率降低仓位。

## 3. 实现内容

### 3.1 候选池与量化优化

- 个股分析师由“最终持仓选择”改为输出 30 只候选股；
- 量化分析师使用自己的因子，从 30 只候选股优化到最终 10 只；
- 其他角色仍保留最终 10 只的选择数量；
- 量化缺席时保留个股分析师的原始排序；
- 两个选股角色均缺席时使用 `deterministic_hash_v1` 中性选择。

### 3.2 趋势确认择时

新增 `calculate_regime_aware_position()`，把趋势状态和波动率目标结合。实现严格按时间截断，避免未来函数。

### 3.3 展示口径修复

前端统一使用：

```text
制度轨 60%：沿用机构现行方案
证据轨 40%：根据正向 Shapley 超额贡献形成建议权重
最终份额：60% × 制度轨份额 + 40% × 证据轨建议权重
```

兼容 JSON 中既有的 `weight`、`old_pool`、`new_pool` 字段名，不修改接口合同。

同时修复说明字段：旧说明把未经上限约束的“相对贡献”写成“权重”，可能出现表格权重 50% 而说明权重 68.3%。现在说明始终显示水位法和 50% 上限处理后的实际证据轨建议权重。

## 4. 测试先行与回归保护

新增测试覆盖：

- 个股分析师输出 30 只候选池；
- 量化分析师接收完整候选池并使用“量化分析师”因子；
- 量化缺席时保留个股分析师排名；
- 正趋势下策略保持满仓；
- 负趋势、高波动状态下策略可以降仓；
- 演示包说明中的证据轨权重与结构化 `weight` 字段一致。

验证命令：

```powershell
python -m unittest discover -s tests -v
python -m compileall -q agent_layer backtest engine scripts tests
node --check engine/web/app.js
git diff --check
```

## 6. 策略角色仍为负的原因

2024 上半年策略仓位为：

| 持有月 | 仓位 |
|---|---:|
| 2024-02 | 85.98% |
| 2024-03 | 100.00% |
| 2024-04 | 100.00% |
| 2024-05 | 100.00% |
| 2024-06 | 100.00% |

策略仅在 2 月因月初之前的趋势为负而防御性降仓，但组合在 2 月随后上涨，策略因此少赚，最终形成约 `-0.56%` 的 Shapley 超额贡献。

这是合理的事前信号在当前样本内失效，并非代码故障。继续降低触发条件或更换区间直到策略转正，会构成样本内结果美化，因此保留真实负值。

证据轨 0% 也不等于最终份额 0%。例如制度轨默认五角色各 20% 时，策略角色的 6:4 合成份额为：

```text
60% × 20% + 40% × 0% = 12%
```

## 7. 结论与后续验证

本阶段实现了“通过公平职责设计尽量提高正向贡献”，结果为 4/5 角色正向；没有实现也不承诺“每个样本期所有角色必然为正”。

下一步应使用多个滚动窗口和严格样本外区间验证角色贡献稳定性，重点观察：

1. 个股与量化角色在不同市场状态下是否持续提供独立增量；
2. 策略角色是否主要在下跌或高波动区间体现价值；
3. 角色排名对候选池大小、趋势窗口和目标波动率的敏感性；
4. 正贡献比例、贡献均值和置信区间，而非单一区间是否全部为正。

## 8. 岗位贡献页空白图表修复

路演模式只展示业务结论，不渲染底部技术图表。旧页面却让“证据轨建议权重”和“Shapley 超额贡献”两个固定高度图表容器默认可见，因此在未生成图表时出现一块半宽、一块通栏的空白区域。

修复内容：

- 两个技术图表的外层容器默认隐藏；
- 每次开始回测时重新隐藏技术图表和双轨对照图；
- 只有结果包含角色明细并开始渲染技术图表时才显示；
- 非分阶段实时回测完成后主动解除技术明细透明状态；
- 新增页面结构回归测试，防止未渲染图表再次占位。
