本轮仅处理第一阶段的结果正确性与回归测试，不调整 Shapley 特征函数定义、角色缺席策略、因子模型或前端布局。

处理内容：

2. 将超额收益结论改为“跑赢 / 跑输 / 基本持平”三态；
3. 将新池规则从“Shapley 绝对值分配”改为“仅正贡献参与奖励分配”；
4. 使用水位法严格执行单角色新池权重不超过 50%；

## 2. 问题与修改

### 2.1 基准收益与超额收益

问题原因：`index_returns` 是按日期索引的收益序列，旧实现读取不存在的 `benchmark_return` 键，因此回退为 0；同时未写入 `excess` 字段。

修改：

- 将指数日收益按月复利；
- 只选择组合实际持有月份，确保组合与基准严格对齐；
- 计算 `excess_return = portfolio_return - benchmark_return`；
- 保留原有响应字段，避免前端接口不兼容。

2024H1 演示结果修复前后：

| 指标 | 修复前 | 修复后 |
|---|---:|---:|
| 组合累计收益 | 21.50% | 21.50% |
| HS300 同期收益 | 0.00% | 7.66% |
| 超额收益 | 0.00% | 13.84% |
| 结论 | 跑输基准 | 跑赢基准 |

### 2.2 超额收益文案

旧实现把所有 `excess_return <= 0` 的情况都描述为“跑输基准”，导致 0 也被判为跑输。

新规则按照页面两位百分比的展示精度设置阈值：

```text
excess > 0.005%   -> 跑赢基准
excess < -0.005%  -> 跑输基准
其他              -> 与基准基本持平
```

FastAPI 结果、Agent 解读和独立 Flask 报告已统一使用三态口径。

### 2.3 负贡献与新池奖励

旧规则使用 `abs(Shapley)` 计算新池权重，负贡献角色仍会因绝对值较大获得奖励。

新规则：

```text
正贡献_i = max(Shapley_i, 0)
加权贡献_i = 正贡献_i * HR调节系数_i
新池权重 = 加权贡献经上限约束后归一化
```

带符号 Shapley 仍完整保留在证据层，用于展示正向贡献或负向拖累；负贡献只是不进入新池奖励分配。角色仍保留旧池 60% 中的现行制度份额。

2024H1 演示中，策略分析师 Shapley 为负，新池权重由原来的约 1% 调整为 0%。

### 2.4 单角色 50% 上限

旧实现先截断到 50%，再整体归一化，归一化会使已截断角色重新超过 50%。修复前行业分析师新池权重为 53.47%。

新实现使用水位法：

1. 将超限角色固定为 50%；
2. 只在剩余角色中重新分配剩余份额；
3. 重复处理直到没有角色超限；
4. 保证权重合计为 100%。

修复后行业分析师新池权重为 50.00%，全部角色权重合计为 100%。

### 2.5 Windows 控制台兼容

完整回测首次复测时，Windows GBK 控制台无法编码启动日志中的 emoji，程序在进入计算前抛出 `UnicodeEncodeError`。

回测核心入口已改用 ASCII 状态标记：`[START]`、`[OK]`、`[ERROR]`、`[PASS]`、`[FAIL]`。增加 GBK 子进程测试，确认非 UTF-8 控制台可以正常进入查询解析并返回规范错误响应。

## 5. 本轮未处理事项

以下问题属于后续阶段，不能因本轮修复而视为已经解决：

1. 当前精确 Shapley 仍以组合绝对收益为特征函数，尚未改为相对 HS300 的超额收益；
2. 各角色缺席时的中性替代策略尚未进行多定义敏感性分析；
3. 尚未补充多时间窗口、样本外、排名稳定性、峰值内存等实验；
4. `main_quantskills.py` 旧版 IC 计算和旧版 LOO 文档仍需在最终统稿前清理；
5. Agent 当前仍以一次规划、一次执行和一次解读为主，尚未实现评估后自动重试闭环。

这些事项应作为第二阶段及后续优化任务单独实施和验证，避免与本次结果正确性修复混在同一变更中。
