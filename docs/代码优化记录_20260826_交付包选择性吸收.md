## 2. 已吸收的必要修改

### 2.1 风控约束不再重新归一化

旧逻辑在执行单股上限和行业上限后，把剩余权重重新归一化到 100%。这会产生
两个错误：

1. 单股上限 5% 处理后又被放大，实际持仓可能重新超过 5%；
2. 策略分析师先降低的整体仓位会被风控重新拉回满仓。

修改后，超过限制的部分作为现金保留，不再重新归一化。默认最终持有 10 只
股票且单股上限为 5% 时，股票总仓位最多为 50%，这是约束组合本身的必然结果，
不是计算缺失。

涉及文件：

- `backtest/risk_control_module.py`
- `tests/test_backtest_engine.py`

### 2.2 行业分析师八因子进入最终组合

旧主链路虽然计算并展示行业分析师的八个 `ind_*` 因子，但最终组合又调用另一套
固定行业模型，导致 Agent 修改的行业因子不能完整影响最终行业筛选。

修改后：

1. 行业分析师仍使用当前因子库登记的八个因子；
2. 每月保留排名靠前的 30 只行业角色样本；
3. 按股票名次进行 Borda 式行业聚合；
4. 聚合得分最高的三个行业进入后续个股和量化环节；
5. 不再在主 Pipeline 中旁路调用旧固定行业模型。

这样保留了当前“5 角色 x 8 因子”的统一产品口径，也让 Agent 调整后的
`factor_config` 真正进入最终回测组合。

涉及文件：

- `backtest/query_engine.py`
- `tests/test_backtest_engine.py`

### 2.3 量化计算性能优化

首次真实回测验证约耗时 8 分钟。热点是 Shapley 32 个联盟中重复计算相同的
量化候选组合，并在每个因子、每只股票上反复扫描完整日线表。

修改后：

- `QuantAnalyst` 先按股票分组，再复用分组数据计算八个因子；
- 单次回测内按月份、候选股票顺序和量化因子配置缓存确定性选择结果；
- 缓存不跨请求，不会让不同用户配置共用结果；
- 同一输入的真实回测结果保持不变。

2024 上半年同一真实回测复测约 90 秒完成，结果与优化前完全一致。

涉及文件：

- `backtest/quant_analyst.py`
- `backtest/query_engine.py`
- `tests/test_backtest_engine.py`

### 2.4 正贡献不足时的权重上限规则

本次真实回测只有一个角色的 Shapley 超额贡献为正。此时以下三个条件无法同时
成立：负贡献角色权重为 0、单角色最多 50%、五角色建议权重合计 100%。

采用的规则为：

1. 优先保证负贡献角色不获得证据轨建议权重；
2. 正贡献角色不足时，按完成 100% 归一化所需的最小幅度放宽实际上限；
3. 返回配置上限、实际上限和是否放宽等结构化字段；
4. 前端 KPI、结论区、技术表和指标解释抽屉明确展示放宽原因；
5. Agent 证据白名单只有在声明完整、实际权重不超过有效上限且负贡献权重为 0
   时才接受放宽结果。

新增或调整的字段：

- `configured_max_role_weight`
- `effective_max_role_weight`
- `cap_relaxed`
- `fallback_equal_weight`

## 4. 真实回测验证

验证请求：

- 日期：2024-01-01 至 2024-06-30
- 基准：HS300
- 调仓频率：月度
- 因子配置：`balanced_equal_v2`
- 归因：五角色 32 个联盟 Shapley 超额收益归因

验证结果：

| 指标 | 结果 |
|---|---:|
| 组合累计收益 | 1.4323% |

50% 放宽至 100%。制度轨仍保留 60%，所以最终 6:4 合成方案并不是其他角色为 0。

## 7. 新策略与默认策略平行对比修复

用户按引导选择预制数据时，旧前端只渲染单个回测结果；实时回测又要求存在
`factorConfigAudit` 才请求默认方案，因此手工调整参数或预制演示路径不会显示
对比区域。

本次修复后：

- 预制演示包同时包含新策略、原始默认策略和同期 HS300 指标；
- 预制回放完成后直接渲染三方平行对比，不再触发现场真实回测；
- 实时回测只要默认配置已加载就生成对照，不再依赖 Agent 审计状态；
- 当前配置与默认配置一致时直接显示零差异，不重复执行同一回测；
- 默认配置加载失败时显示明确错误，不再静默隐藏对比区域；
- 预制对照标注为“已验证预制结果”，避免被误解为现场计算。
- 前端以 `no-store` 方式读取最新静态预制对照；即使当前后端进程仍缓存旧版演示
  对象，也能补齐三方对比，无需为了更新演示包而重启服务。
- 预制模式明确说明其回放的是官方新策略；任意自定义参数仍需选择实时回测。
- 三方对比新增“新策略 / 原始默认策略 / HS300”累计收益折线图；三条曲线从
  0% 同一起点出发，按同月份收益连续复利，表格继续保留用于核对精确指标。
- 预制包保存新旧两套完整月度序列；实时模式使用客户回测与默认回测各自返回的
  `time_series`，不使用汇总指标倒推曲线。
- 前端主脚本增加本次功能的版本标识，避免浏览器复用旧版 `app.js`，造成代码
  已更新但普通刷新后对比折线仍不出现。
- 驾驶舱第3步由单一组合收益图升级为三方案累计收益主图。回放计算过程中先展示
  新策略进度；默认方案对照就绪后，同一主图直接展示新策略、原始默认策略和
  HS300，用户无需滚动到技术明细区寻找默认方案曲线。
- 主图中的原始默认策略使用黄色虚线和节点，新策略使用青色实线，HS300使用
  紫色虚线，避免三条收益路径在紧凑驾驶舱中难以区分。
