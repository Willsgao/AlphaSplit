# 6:4 双轨分配机制

本文档说明 AlphaSplit 如何把「贡献计量」用于广义价值分配决策。分配机制是调动各角色参与积极性、促进投研协同的手段，长期目标是促进投资回报改善；历史回测不构成收益承诺。

---

## 1. 与立项文档的关系

课题立项描述（2026-08-12）规定：

- 系统输出 **贡献系数 + 归因解释**，作为评审委员会的量化证据，而非最终裁决；
- 五类角色的贡献陈述仅供评审参考，不参与建议份额计算；
- 保留 **评审委员会（或机构治理责任人）独立确认** 环节，系统不替代机构治理，也不自动执行分配；
- 与 KPI / 主观评议对照，提供可解释、可追溯的量化证据。

立项文档**未规定**具体分配比例。本项目的 **6:4 双轨制** 是在上述框架下的**落地产品设计**：在尊重机构既有制度的前提下，将夏普利证据渐进接入价值分配决策。

---

## 2. 双轨定义

对可分配资源池 `P`，各角色 `i` 的建议份额为：

```text
建议份额_i = 60% × 现行份额_i + 40% × 夏普利证据池份额_i
建议资源量_i = 建议份额_i × P
```

| 轨道 | 比例 | 含义 | 数据来源 |
|------|------|------|----------|
| **旧池** | 60% | 沿用机构提交的**现行分配方案**（制度、历史惯例、治理责任人确认的比例） | 用户录入 / 机构档案 |
| **证据池** | 40% | 按 HS300 回测 **夏普利边际贡献** 动态形成的分配建议 | `query_engine` 回测输出 `role_breakdown.weight` |

要点：

- **旧池 60%**：系统不替机构重写历史制度，只读取并保留用户现行方案；
- **证据池 40%**：仅计量五投研角色（行业 / 个股 / 策略 / 量化 / 风控）在 Pipeline 内的边际贡献；
- **合成结果**：可用于资金预算、研究资源、项目机会、数据/算力额度和激励权益等广义分配，须经评审委员会（或机构治理责任人）确认后方可应用。

可选：证据池内部可叠加制度调节系数 `role_weights`（API 已支持），用于体现「制度偏好」对证据权重的调节。

---

## 3. 与回测引擎的对应关系

| 模块 | 职责 |
|------|------|
| `backtest/query_engine.py` | 计算**证据池 40%** 内各角色权重（夏普利 → 归一化） |
| `backtest/main_quantskills.py` | 完整 6:4 合成示例（含基金经理等非动态角色旧池权重） |
| `engine/web/app.js` | 评审决策页展示旧池 / 新池 / 合成表，支持编辑现行份额 |

回测结论页侧重 **证据生成**（新池建议 + 夏普利排名）；**6:4 合成表** 放在 **评审委员会决策** 主舞台。

---

## 4. 演示默认参数

Web 演示在无机构档案时采用：

- 可分配资源池示例：`10,000,000` 个资源单位
- 旧池现行份额：五角色**均等 20%**（可编辑，合计应为 100%）
- 新池份额：取自最近一次 HS300 回测的 `role_breakdown[].weight`

机构落地时替换为真实现行方案即可，公式不变。

---

## 5. 路演话术（可直接引用）

> 我们不是用夏普利全盘推翻既有制度。  
> **60% 沿用贵司现行分配，40% 按真实回测证据动态校正**；  
> 系统给出合成建议与完整证据链；五类角色可陈述意见，但只供参考，不改变系统建议。
> 最终由**评审委员会（或机构治理责任人）独立判断、调整并确认**后方可应用。更合理的分配用于激发参与和协作，并以长期投资回报改善为目标。

---

## 6. 产品流程

```text
HS300 多角色回测
    → 夏普利贡献 + 新池 40% 建议权重（回测页）
    → 录入 / 确认现行份额（旧池 60%）
    → 6:4 合成表 + 资源量（评审决策页）
    → 五类角色陈述贡献意见（仅供评审参考，不参与建议计算）
    → 评审委员会 / 机构治理责任人独立调整并确认
```
