# AlphaSplit 代码优化记录（2026-08-26）

## 一、优化目标

本轮围绕“客户专属投资方案”完善闭环：客户通过快捷选项和自然语言表达风险、目标与角色偏好，DeepSeek Agent 将意图转换为受约束的因子配置建议，经后端校验和人工确认后再进入回测。语音交互不在本轮范围内。

核心流程：

```text
客户偏好/文字对话
→ DeepSeek理解投资意图
→ 生成结构化因子配置补丁
→ 后端白名单与数值校验
→ 人工确认
→ 客户专属回测
→ 客户方案/默认方案/沪深300同口径对比
```

## 二、主要修改

### 1. 40因子配置登记与方向修正

- 建立五角色、40因子的统一登记表，补充中文名称、类别、含义和高值/低值偏好方向。
- 对波动率、下行波动、ATR、区间波动和峰度等风险指标使用低值优先方向，避免“波动越高得分越高”的反向逻辑。
- 默认配置标识更新为 `balanced_equal_v2`。每个角色内部的8个因子仍以12.5%等权作为初始化基线，该数值不代表最优组合。
- 因子权重在角色内部归一化为100%，后端强制单因子最终权重不超过35%。

涉及文件：

- `backtest/factor_config.py`
- `backtest/query_engine.py`
- `backtest/quant_analyst.py`

### 2. DeepSeek 因子 Agent

- 新增结构化因子 Agent，仅允许返回已登记的角色、因子和模块参数。
- 支持多轮文字上下文、风险偏好、关注目标和关注角色等快捷选择。
- 信息不足时返回澄清问题，不修改配置。
- DeepSeek调用失败、超时、JSON错误或输出越界时，明确标记为 `rule_fallback`，不会伪装成模型结果。
- Agent 只生成建议，不执行回测；用户必须点击“确认并应用配置”。

涉及文件：

- `agent_layer/impl/factor_agent.py`
- `agent_layer/impl/llm.py`
- `engine/integrations/agent_bridge.py`
- `engine/api/models.py`
- `engine/api/main.py`

### 3. 前端互动与审计

- 新增“客户投资方案 Agent”操作区，采用快捷选择与自由文字相结合的混合交互。
- 展示 DeepSeek 在线、规则模式或规则回退状态。
- 展示每一项建议的当前值、建议值、方向和原因，并保留40因子配置审查入口。
- 人工确认后记录配置来源、模型、确认时间、摘要和本轮变更；未确认的建议不会传给回测。
- 支持 `Ctrl+Enter` 发送文字需求。
- 五角色协商启动后自动定位到实时对话区，协商完成后自动定位到人工确认区，减少手动滚动。
- 移除比赛网页中早期三人场景的实验规划、回平衡、三组对照、演化和旧公式页面；技术附录统一为当前五角色方案的因子、回测、夏普利和人工确认说明。
- 页面默认进入答辩状态：2024上半年HS300、月度调仓、启用缓存，并预选“稳健、控制回撤、风控”和标准客户需求，减少现场输入与筛选。

涉及文件：

- `engine/web/index.html`
- `engine/web/app.js`
- `engine/web/style.css`

### 4. 客户方案回测与三方对照

- 实时回测请求携带已确认的 `factor_config`。
- 后端将配置用于角色因子综合评分、量化候选优化、目标波动率和风险约束。
- 客户方案完成后，前端使用相同日期、股票范围、基准和调仓频率获取默认方案结果。
- 结果页展示客户方案、默认等权方案和沪深300的累计收益、超额收益、夏普比率和最大回撤，并给出客户方案相对默认方案的变化。
- 对照只用于说明配置差异，不作为收益承诺，也不用于基于历史结果反复调参。

### 5. 安全与密钥管理

- API Key 仅从服务端环境变量 `DEEPSEEK_API_KEY` 读取。
- 密钥不进入前端、不写入配置文件、不写入日志、不纳入Git。
- 健康检查和配置接口只暴露模型是否可用、供应商和模型名。

## 六、Agent可靠性与证据约束增强

本次参考早期 Agent 交付包中有价值的工程设计，仅吸收可靠性、可信边界和审计思路，未引入 Hermes、飞书适配器或另一套任务框架。

### 1. DeepSeek调用可靠性

- 保持现有 `call_llm(...) -> str` 接口不变，增加 `429`、`500`、`502`、`503`、`504` 和连接超时的有限重试。
- 默认最多重试1次，可通过 `AGENT_LAYER_LLM_MAX_RETRIES` 设置为0到3次。
- 重试间隔由 `AGENT_LAYER_LLM_RETRY_BACKOFF` 控制，服务端限制为0到2秒。
- 当模型端不支持 JSON Schema 时，可自动降级为 JSON Object；不从自然语言响应中用正则猜测JSON结构。
- 将超时、连接失败、HTTP错误和响应结构错误转换为稳定错误码。
- 记录供应商、模型、耗时、请求次数、响应格式、降级状态和错误码；不记录API Key、完整提示词、完整服务地址或原始错误正文。

涉及文件：

- `agent_layer/impl/llm.py`
- `tests/test_llm_provider.py`

### 2. 因子建议审计轨迹

- 每次因子建议生成独立审计号，并记录配置调整前后指纹、变更数量、建议来源和是否需要人工确认。
- 执行阶段统一为：输入归一化、意图解释、约束校验、人工确认。
- DeepSeek调用成功时记录安全调用元数据；模型失败转规则建议时明确标记 `fallback`。
- 原始用户提示词不复制进审计元数据，前端只展示审计号、配置指纹和必要的调用次数/耗时。
- 人工确认后，将本次 Agent 审计信息随前端配置确认记录一并保存。

涉及文件：

- `agent_layer/impl/factor_agent.py`
- `engine/web/app.js`
- `tests/test_factor_agent.py`
- `tests/test_api.py`

### 3. 回测证据白名单与可信边界

- 新增只读证据构建器，原始回测结果不会被修改。
- 只向解读 Agent 提供累计收益、基准收益、超额收益、夏普比率、最大回撤、角色权重和Shapley贡献等白名单字段。
- 自动检查有限数、最大回撤范围、`超额收益=组合收益-基准收益`、角色权重合计100%、单角色50%上限，以及声明为超额收益口径时的Shapley可加性。
- 不一致字段会被隔离并生成结构化警告，不再进入标题、权重排序或LLM提示词。
- 每项可信数据生成 `E001` 形式的证据编号；LLM数值解读必须引用合法证据编号，未知证据、无引用数值和收益承诺会触发确定性解读降级。
- 前端Agent报告展示“证据校验通过”或“异常字段已隔离”状态。

涉及文件：

- `agent_layer/impl/evidence.py`
- `agent_layer/impl/interpreter.py`
- `agent_layer/contracts.py`
- `engine/web/app.js`
- `tests/test_agent_evidence.py`

## 七、前端数据可解释性增强

根据“前端展示的每一个核心数据都应有可解释性”的评审意见，新增统一的数据依据抽屉，避免把大段公式直接堆在主页面。

### 1. 交互方式

- 首页关键指标和各结果表数值旁增加信息按钮。
- 桌面端点击后从右侧打开“数据依据”抽屉；移动端显示为底部面板。
- 抽屉统一展示当前值、定义、公式、本次代入、时间范围、基准、后端字段、证据编号、请求编号、配置编号和使用边界。
- 支持点击遮罩、关闭按钮和 `Esc` 关闭，并将焦点还给原按钮。

### 2. 已覆盖数据

- 组合累计收益、沪深300累计收益、超额收益、年化夏普比率、最大回撤。
- 五角色夏普利超额贡献、相对贡献和证据轨建议权重。
- 40个因子权重、策略/风控模块参数及Agent建议调整前后值。
- 客户方案、默认等权方案、沪深300三方对照及差值。
- 6:4双轨中的制度轨输入、证据轨权重、合成份额、合成资源量。
- 五角色协商建议、带宽、合成锚点和人工确认输入。
- 角色权重图、夏普利贡献图和6:4双轨对照图采用图表级解释入口。

### 3. 公式与追溯口径

- 累计收益使用各期收益连续复利：`R = ∏(1+r_t)-1`。
- 超额收益使用组合累计收益减同期沪深300累计收益。
- 夏普比率与后端一致，使用2%年化无风险利率和月度收益年化波动率。
- 夏普利特征函数为 `v(S)=R(S)-R(沪深300)`；五角色共32个理论联盟、31个非空联盟回测。
- 证据轨权重只使用正向夏普利得分，归一化后执行单角色50%上限。
- 解释抽屉读取Agent证据白名单中的 `E001` 等证据编号，并显示本次 `request_id` 与因子 `config_id`。

涉及文件：

- `engine/web/index.html`
- `engine/web/style.css`
- `engine/web/app.js`

## 八、首次用户自助流程重构

针对首次使用者无法判断“从哪里开始、下一步做什么”的问题，前端主线调整为四个按顺序解锁的步骤：

1. 描述投资需求：选择风险偏好、投资目标和关注角色，或直接与Agent对话。
2. 确认Agent方案：查看调整前后值和原因，人工确认后配置才生效。
3. 回测并理解结果：选择预置数据快速体验，或使用已确认客户方案进行实时回测。
4. 形成应用建议：查看角色贡献，进入6:4双轨合成并完成最终人工确认。

页面新增“现在该做什么”提示区，随流程更新标题、说明和唯一主按钮；未来步骤在前置动作完成前保持锁定。生成建议、确认配置、完成回测和最终确认后，页面会自动更新步骤并定位到下一操作区域。

为减少入口冲突，原“Agent规划回测”、回测参数、缓存和技术日志默认移入“专业模式”；算法能力和接口保持不变。顶部“一键路演”改为“观看完整演示”，与普通用户的自助体验明确区分。

验证结果：完整测试共85项全部通过；浏览器已验证默认高级区隐藏、专业模式切换、主按钮自动定位、未完成步骤锁定、预置回测完成后自动解锁第4步、进入6:4应用建议，以及390×844视口下四步流程以两列两行显示且无横向溢出。

### 应用建议与协商衔接修正

- 在6:4合成表底部新增“下一步：开始五角色协商”，用户无需返回页面顶部寻找入口。
- 原“确认方案（人工）”改为“采用当前输入作为协商基准”，避免与协商后的最终人工确认混淆。
- 点击底部协商按钮时读取当前制度轨输入，随后自动展示协商过程，并定位到协商建议和最终人工确认区域。

### 分配比例口径与下一步引导强化

- 6:4表格明确区分三种比例：原有方案比例（仅制度轨内部）、纯新方案比例（仅40%证据轨内部）、最终合成比例（占总可分配资源池）。
- 系统建议案和人工确认区同时展示纯新方案比例与最终合成锚点，并明确人工输入已经包含60%原有方案和40%纯新方案。
- 协商发言中的“主张新池内”修正为“主张总资源池份额”，避免把最终协商比例误解为40%证据轨内部比例。
- 为当前唯一可执行的下一步按钮增加状态标签、轮廓呼吸与箭头提示；生成建议、人工确认、回测、进入应用建议和五角色协商后，高亮会自动转移到下一操作。
- 回测阶段默认将“使用预置数据快速体验”设为下一步；“运行我的方案回测”作为验证已确认客户因子配置的可选操作保留。
- 页面刷新时关闭浏览器旧滚动位置恢复；初始化完成后检查当前有效的下一步按钮，仅在按钮不在视口内时自动居中定位。
- 动效遵循系统“减少动态效果”设置，移动端保持按钮整行展示。
