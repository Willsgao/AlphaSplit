# AlphaSplit 第二阶段代码优化记录（2026-08-25）

## 1. 优化目标

本阶段针对第一阶段审查确认的高优先级问题，按“先写失败测试、再修改实现、最后完整回测”的顺序执行。

目标：

1. Shapley 归因从组合绝对收益改为相对 HS300 的超额收益；
2. 任一联盟回测失败时禁止继续生成正式归因结果；
3. 基准缺少组合持有月份时禁止按零收益填充；
4. 消除角色缺席策略对股票列表载入顺序的依赖；
5. 收紧真实回测 API 参数，增加单任务互斥和公开演示保护；
6. 锁定已验证依赖，分离安装与前台启动；
7. 用新实现重新执行完整回测并更新网页演示包。

## 2. 分阶段方案与执行结果

### 2.1 阶段一：建立失败测试

新增测试锁定以下不变量：

- `sum(Shapley) == 组合收益 - 同期HS300收益`；
- 任一非空联盟异常时返回 `COALITION_BACKTEST_FAILED`；
- 基准缺少组合持有月份时返回 `BENCHMARK_DATA_MISSING`；
- 中性选股结果与输入列表顺序无关；
- 未知 API 字段和倒置日期区间返回 HTTP 422；
- 已有回测运行时第二个任务返回 HTTP 409；
- 公开演示模式禁止访问历史结果和真实回测；
- 路演演示包本身满足超额收益 Shapley 不变量。

修改实现前，上述测试分别因旧的绝对收益口径、异常按零处理、`fillna(0)`、列表切片和宽松字典模型而失败，证明测试能够识别目标问题。

### 2.2 阶段二：超额收益 Shapley

新特征函数定义：

```text
v(empty) = 0
v(S) = R_pipeline(S) - R_HS300(aligned months), S != empty
sum(phi_i) = v(N) = R_full - R_HS300
```

实现要点：

- 每个联盟均使用自身实际持有月份与 HS300 月收益严格对齐；
- 空联盟解释为仅持有基准，因此超额收益为 0；
- 全角色 Pipeline 首次结果在全联盟处复用，避免重复执行；
- 响应新增 `characteristic_function=excess_return_vs_hs300`；
- 保留 `total_return`、`benchmark_return`、`excess_return` 等既有字段，避免前端接口破坏；
- 前端实时进度明确显示“联盟超额收益”，演示回放明确显示“角色 Shapley 超额贡献”。

### 2.3 阶段三：失败中止与数据完整性

旧实现捕获任意联盟异常后把 `v(S)` 设为 0，仍继续生成结果。新实现：

- 联盟执行异常立即终止整次归因；
- 返回错误码 `COALITION_BACKTEST_FAILED` 和具体联盟名称；
- 不再允许被污染的 `v_cache` 通过 Shapley 有效性校验；
- HS300 缺少任一组合持有月份时返回 `BENCHMARK_DATA_MISSING`；
- API 分别映射为 HTTP 500 和 HTTP 422。

### 2.4 阶段四：中性替代策略

旧实现用 `stocks[:TOP_N]` 选择角色缺席时的股票，结果会受到字典或 CSV 载入顺序影响。

新策略 `deterministic_hash_v1`：

1. 股票代码去重并转为字符串；
2. 使用固定命名空间、持有月份和股票代码计算 SHA-256 排序键；
3. 选择排序后的前 `TOP_N` 只并等权持有；
4. 相同月份和股票池始终得到相同结果，输入顺序变化不影响结果；
5. 个股分析师缺席但量化分析师存在时，将完整候选池交给量化模块，不提前任意截断。

该策略不是唯一可能的经济学中性定义，后续仍需与全池等权、行业内等权和市值基准方案做敏感性比较。

### 2.5 阶段五：API 与公开演示安全

真实回测请求改为结构化 Pydantic 模型，明确校验：

- 日期格式和起止顺序；
- 角色、基准、调仓频率、粒度和归因方法枚举；
- 制度调节系数的角色名、有限性和非负性；
- 未知字段直接拒绝，防止拼写错误进入耗时任务。

运行保护：

- 同一进程只允许一个真实回测任务；
- 忙碌时返回 HTTP 409 / `BACKTEST_BUSY`；
- `ALPHASPLIT_PUBLIC_DEMO_ONLY=1` 时只开放健康检查、元信息和官方演示包；
- 设置 `ALPHASPLIT_API_TOKEN` 后，真实回测、Agent Pipeline 和历史结果要求请求头 `X-AlphaSplit-Token`；
- Token 使用常量时间比较。

### 2.6 阶段六：依赖与启动职责

- 新增 `requirements-lock.txt`，记录 Python 3.11 / Windows 已验证版本及直接传递依赖；
- 新增 `install.ps1`，只负责安装锁定依赖；
- `start.ps1` 删除每次启动前的 `pip install`，只在当前 PowerShell 前台启动服务；
- README 增加公开演示模式和 Token 配置说明。

## 3. 完整真实回测验证

调仓：monthly
角色：5

## 6. 后续事项

本阶段完成了已确认的 P1 正确性问题和主要工程保护，但以下事项仍应继续推进：

1. 增加 Playwright 浏览器端到端测试并接入持续回归；
2. 对不同中性替代策略、多时间窗口和样本外区间做排名稳定性分析；
3. 增加短窗口真实数据集成测试，减少仅在完整慢回测中发现问题的风险；
4. 评估将同步长任务改为任务队列，提供任务状态、取消和超时；
5. 对 `hr_weight`、`new_pool` 等历史兼容字段制定版本化迁移方案；
6. Agent 增加结果评估、失败诊断、重规划和终止条件，形成受控闭环。
